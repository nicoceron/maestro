## Current verification

- Identity: headless Fortify login/logout/reset/verification, Maestro-owned public registration, ten-minute password/passkey confirmation, encrypted TOTP setup/recovery with ten-minute pending-setup expiry, post-confirmation-only recovery-code disclosure, and a replay-resistant five-minute challenge, official exact-origin WebAuthn passkeys, safe passkey/current-user metadata, database session inventory/revocation with stale-record pruning and idle/absolute limits, JSON-body studio invitations, fragment credential scrubbing, and two-path onboarding are scaffolded. Public and invitation-bound registration use one generic unauthenticated `202` for new, existing, and semantically unusable invitation cases; registration does not log in or rotate the CSRF session, only an eligible new identity receives the encrypted queued verification notification, every semantic path performs password-hash work inside the timebox, and HMAC-keyed account/IP limits apply. Passwords are minimum 12 characters, confirmed, and uncompromised checked without mixed-case/number/symbol composition requirements, so passphrases remain valid. Password-reset invalidation, trusted browser boundaries, and membership/invitation/user-session RLS are covered. The invitation domain now also proves capability-driven list/create/resend/revoke, fresh-token supersession, old-token invalidation, token-safe versioned queued delivery with pending-intent recovery, immutable tenant audit events, restricted-runtime RLS, and idempotent 30-day terminal-digest cleanup. Mandatory privileged-role MFA/grace, the platform session profile, complete security notifications, and cross-domain immutable audit/outbox remain incomplete; the [invitation delivery acceptance contract](../security/invitation-audit-delivery-acceptance.md) records the implemented boundary without completing those broader platform capabilities. Continue against [Laravel 13 Fortify's contracts](https://laravel.com/docs/13.x/fortify) and the [stable identity acceptance IDs](../security/identity-access-acceptance.md#12-stable-identity-control-ids).
- People: the tenant API now scaffolds filtered/paginated list, atomic create, privacy-aware detail, optimistic PATCH, and versioned student-status transitions with immutable history. Typed student/staff profiles, instrument/tag assignments, and definition-validated custom fields are present; billing contact/search and student visibility are payer-scoped, cross-studio identifiers cannot escape the tenant, and public history excludes global actor IDs. The Filament resource now exposes the corresponding policy-scoped directory, profile forms, lifecycle actions, configuration surfaces, and versioned household editor. This does not complete CRM parity: guardian/adult-student lifecycle, duplicate merge, bulk actions, CSV round trip, portal/self-service rules, complete audits/outbox, and production E2E/accessibility remain missing. Continue against [Laravel 13 API resources](https://laravel.com/docs/13.x/eloquent-resources), [Laravel authorization](https://laravel.com/docs/13.x/authorization), [Filament 5 resources](https://filamentphp.com/docs/5.x/resources/overview), and [Filament security](https://filamentphp.com/docs/5.x/advanced/security).
- Scheduling: SCH-01 through SCH-08 now have a tenant-scoped foundation: versioned services/effective configuration, composite location/room/equipment boundaries, linked-teacher availability/time off/travel rules, RFC 5545 recurrence and materialized occurrences, translated clone/future/series recurrence sets with preserved history, holds and roster preview/commit, cursor-paginated role-projected public/studio calendars, hard/soft conflict checks, advisory slot ranking, and server-owned create/clone/reschedule/cancel/restore previews. Scheduling previews are actor/studio/version bound, hard conflicts are non-overrideable, exact replay is idempotent, and billing/payroll/conditional make-up effects are explicit projection intents only. The Filament calendar and configuration surfaces use the same domain/query paths. The real Chromium gate now covers login, tenant navigation, calendar timeline/agenda controls, keyboard focus, WCAG axe analysis, 390-pixel overflow, and a deterministic Linux calendar snapshot. These rows remain scaffolded until exhaustive PostgreSQL concurrency/load and populated external journeys are complete. The exact boundary is [Scheduling and attendance acceptance](scheduling-attendance-acceptance.md).
- Attendance and notes: normalized single/bulk/express attendance, immutable optimistic corrections, overdue management work, relationship projection, billing redaction, sanitized participant/group notes, author-private enforcement, immutable revisions, templates, previewed recipient delivery, transactional outbox intent, and private fail-closed attachment quarantine/scan/download are present. Clean attachment metadata is fingerprinted into delivery preview/commit; unsafe or retired files remain nondownloadable, and signed downloads reauthorize current access plus recent identity at use time. The browser gate covers honest teaching/template empty states, keyboard-first template creation, WCAG analysis, and mobile containment. ATT-01/02 remain scaffolded because offline conflict sync, provider-delivery completion, and populated teaching/delivery/attachment browser journeys are not yet accepted; ledger effects belong to ATT-03/04.
- Platform operations: FND-07 now has a forced-RLS, tamper-evident tenant audit projection plus explicitly approved read-only support sessions that preserve the platform actor, require recent identity and a separate current-session TOTP proof, disclose their bearer once, and currently expose only delegated `audit.read`. FND-09 has the transaction-required encrypted producer, aggregate sequence, after-commit relay, expiring lease, stale-token rejection, bounded retry, dead letter, and explicit tenant-context foundation. FND-10 has owner-only idempotent encrypted exports, a checksummed secret-excluding manifest, one-use signed download, optimistic retention/studio-wide hold, 14-day cooling-off, independent approval by a distinct active studio administrator, 30-day reversible quarantine, and a non-writing archive verification drill. The combined focused SQLite run passes 21 tests / 163 assertions with four intentional PostgreSQL-only skips. Clean PostgreSQL 18 restricted-runtime evidence passes audit/outbox/support at 17 tests / 118 assertions and tenant data at 8 tests / 74 assertions with no skips; audit evidence includes four concurrent writer processes with contiguous sequence and an unbroken hash chain. The [stable acceptance matrix](platform-operations-acceptance.md#6-current-evidence-boundary) keeps these families scaffolded because full domain adoption, broader concurrency/load, consumer inbox/telemetry, consistent snapshot/file round trip, scoped legal hold, irreversible purge/key destruction, archive activation, fault rollback, and browser/a11y proof remain missing.
- Laravel: the current SQLite suite passes all 242 tests with 220 passed, 2,538 assertions, and 22 intentional PostgreSQL-only skips.
